Before you start

You need a scoped proxy key from this deployment. Keys are never shown on this page.

  1. Get a scoped proxy key

    An administrator provisions a durable key with knowledge:read. Add knowledge:manage only if the agent should administer sources and allowances. Access-page keys survive Container restarts only with an external control-plane database.

  2. Store it privately

    Put it in your shell profile or secret manager, not in a prompt, repository or chat.

    Shell environment
    export MULTILLM_KNOWLEDGE_API_KEY="your-scoped-proxy-key"
  3. Connect your client

    Let your agent configure itself with the setup prompt, or follow the Codex or Claude Code steps below.

Verify the connection

Configuration alone does not prove access. Confirm it with a small real request.

  1. List the tools

    A key with both scopes sees all {{ tools | length }} tools; a knowledge:read key sees {{ read_tools | length }}.

  2. Ask a small evidence question

    For example, the request-size limit of a dependency in your project. Expect cited excerpts, a version basis and any coverage gaps.

  3. Read the limitations

    Missing providers, disabled allowances or unindexed sources are reported, not hidden.

If something fails
SymptomLikely cause
401 authentication requiredThe client did not send the key; export the variable and restart the client.
Tools missing or scope errorThe key lacks knowledge:read or knowledge:manage. Provider keys cannot authenticate here.
setup_neededThis deployment has not connected its private Knowledge service yet.
Insufficient evidenceNo retained or live source covers the question or version; the response lists the gaps.
