LLM routing

Choose how each request is routed

OpenAI-compatible clients keep their request and streaming format. The model value decides the contract, so nothing is substituted silently.

provider:model

Explicit

Chat, Responses and images go to exactly one provider through /v1/chat/completions, /v1/responses or /v1/images/generations.

auto:name

Automatic chat

An operator-ordered list of candidates. The next one is tried only after a definite rejection before generation: 401, 402, 403, 404, 429 or an open circuit. Timeouts and generic 5xx responses are not replayed.

/provider/…

Provider native

Provider-specific paths preserve each upstream protocol, such as Anthropic Messages, Gemini or the Responses API, with no cross-provider substitution.

Knowledge retrieval

Evidence with its sources, versions and gaps

Knowledge returns cited excerpts rather than generated answers. Requested and observed versions stay separate, and missing evidence is reported instead of filled in.

Cited excerpts

Each excerpt links to its original source with the observed version, the evidence for that version and a byte range in the retained snapshot.

Retained sources

Operators register public documentation, refresh it through Firecrawl or Exa, and query the indexed snapshots. Only approved hosts are fetched.

Allowances first

Every provider allowance starts at zero. Confirmed, pending and unknown outcomes all count, so an uncertain call is never assumed free.

Alexandria structured data

Discovering and inspecting a capability is free. Retrieval spends its published Firecrawl credits and returns a receipt you can check again without paying twice.

Access

Knowledge administration

Sources, indexing jobs, allowances and Alexandria, with configuration and live access kept distinct.

Workbench

Saved connection profiles, blind route comparisons and session diagnostics, with billed calls confirmed first.

Safeguards

Defaults that keep keys and costs contained

  • Server-side credentials. Browsers and clients never receive provider keys; the dashboard calls providers through the server.
  • Single-attempt images. Image requests never fail over automatically, so a timeout cannot trigger a second paid generation elsewhere.
  • Body-free telemetry. Request records keep route, status, latency and cost estimates, not prompts or responses.
  • Public pages stay public. This page and the agent resources contain no account, source or configuration state.
